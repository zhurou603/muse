## 一、什么叫"违规造假"——赛题里的红线分三档

赛题的审查条款写得很具体（"复现审查与违规处理"一节），我按严重程度翻译成大白话：

### 第一档：直接取消成绩/资格的"造假"行为

| 条款原文 | 实际含义 | 典型作死场景 |
|---|---|---|
| **使用隐藏测试标签、测试集等价标签** | 不能碰 B 榜答案，也不能碰"实质上等于答案"的东西 | 例：B 榜某任务是"某性质 X"，你去外部数据库查到了这些分子已发表的 X 实验值混进训练——哪怕 B 榜测试集本身没公开，这也算 |
| **通过外部数据库查询目标性质** | 推理时不能联网查答案 | encode.sh 在无网络环境运行，这条就是用运行环境物理封堵的 |
| **测试集反向工程** | 不能根据提交反馈反推测试集 | 例：A 榜每天能提交一次得分，你构造特殊预测文件，通过返回分数二分逼近真实标签 |
| **伪造复现材料** | 交的训练代码/配置/种子是假的 | 例：实际用了 5 个模型的集成，但复现材料里只写了一个；或者权重根本不是声明的流程训出来的 |
| **未声明数据** | 训练用了清单之外的数据 | 用了某数据集但嫌麻烦没写进 data_manifest，被审查发现 = 视为作弊，不管它有没有提升 |

### 第二档：技术违规（子任务记 0 分或违规判定）

- **未经改变的开源 Encoder 直接提交**——加载一个 Uni-Mol 官方权重就交，违规；你必须续训/改造/蒸馏，且能证明"改变"的过程
- **用 A 榜以外的有标签数据训练**——预训练只能吃无标签数据，有标签的只能是官方 A 榜训练集
- **不同任务加载实质不同的 Encoder 主体**——表面交一个权重文件，实际每个领域偷偷换模型，违规
- **表征依赖批次组成或顺序**——比如在 Encoder 里偷偷做 batch 内归一化，让同一条记录在不同批次里表征不同
- **MLP 超标**——超过 2 层/100K 参数，或夹带校准、阈值、检索等后处理
- **手工改得分文件**——score.py 生成的文件一个字符都不能动

### 第三档：复现失败（可解释，但解释不了就出局）

这一条最容易误伤老实人：**主办方会真的重跑你的训练**，如果你的复现分数和提交分数差距"显著"且你给不出技术解释（比如非确定性算子导致的正常波动），照样取消资格。所以"我没造假，但我自己也复现不出来"在这个比赛里不是免责理由。

## 三、几个关键的实现细节（比 loss 选型本身更容易踩坑）

**1. 能量/力的权重配比。** 力是逐原子监督，单条样本的信号量是分子级能量的几十倍。按 OC20/UMA 系的经验惯例，力 loss 权重要显著高于能量（典型量级 10–100:1），否则能量项主导梯度、力学不到东西。如果做保守力场（力 = 能量对坐标的负梯度），物理一致性更好但反向传播二阶导贵约 3 倍；24 天窗口内建议**直接预测力**（非保守头），性价比更高。

**2. 多任务异构尺度的归一化。** 能量（几千 Hartree）、偶极矩（几个 Debye）、MIC（log 浓度）量纲差了十几个数量级，混在一个 loss 里必然是大尺度任务吃掉梯度。标准做法：**每个任务的标签用训练集统计量 z-score 标准化**（用训练集算均值方差是合法的），模型预测标准化值；每条 loss 再除以其任务的标准差平方（即 Kendall 不确定性加权的简化版）。回归 loss 用 Huber 而非纯 MSE——标签噪声在 DBAASP 这类实验测量数据上很真实。

**3. 坐标去噪的 σ 调度。** 单一噪声水平学到的几何信息很窄；建议 σ 在 0.04–1.0 Å 区间对数均匀采样，并把 σ 作为条件嵌入喂给模型（score matching 标准做法）。这个任务和"力"在数学上是近亲（去噪分数正比于对数密度的梯度），二者联合训练有协同。

**4. 描述符蒸馏头要"宽而浅"，且从中间层读出。** 200 维描述符回归头挂在主干中部+尾部两个位置，迫使性质信息分布在多层——这对后续"多层加权读出"的表征构造是配套的。所有描述符由输入分子自己算出来，**零外部数据、零审计负担**，是整个 loss 组合里性价比最高的一项。

**5. A 榜标签的正确混入方式。** 如果要用：单独一组任务头，loss 总权重压到 5% 以下，并且**只对训练集**（绝不碰 A 榜验证/测试标签进 Encoder）；同时用它监控"贴 A 榜"的程度——如果你在自建"性质留出"影子验证集上看到泛化掉分，第一时间砍的就是这组 loss。

## 一、先对齐世界观：这里的"token"是什么

所以"Encoder"就是一个处理原子图的 Transformer。Uni-Mol2 就是这样：原子是一轨 token，"原子对"（任意两个原子之间的关系，如距离）是另一轨 token。

## 二、预训练 loss：全都对应你熟悉的"下一个 token 预测"，只是被预测的东西变了

你理解 BERT 的掩码语言模型吧？遮住一个词，让模型猜。科学预训练的核心 loss 全是这个套路的变体，**区别只在"遮住什么、猜什么"**：

**1. 掩码原子预测（= BERT 的 MLM）**
随机遮住 15% 的原子类型（比如把这个碳盖住），让模型根据周围原子和几何结构猜它是什么元素。损失函数就是你熟悉的交叉熵。这教模型"化学环境决定原子身份"——和"上下文决定词义"是完全同构的学习。

**2. 坐标去噪（= 扩散模型的训练目标，也≈连续版 MLM）**
给原子的真实 3D 坐标加一点随机噪声，让模型预测"噪声是多少"（等价于预测真实坐标在哪）。文字是离散的，没法"遮一半"，但坐标是连续值，所以"盖住"的方式是加噪声。这教模型"合理的分子几何长什么样"——原子间距多少、键角多大。可以理解为**化学界的"下一个 token 预测"，只是预测的是连续几何而不是离散词**。

**3. 能量/力/应力回归（这个没有 NLP 对应物，是科学域独有的"免费答案"）**
这是最关键、也最需要解释的一个。量子化学计算（DFT）能算出每个分子结构的**总能量**和**每个原子受到的力**（把原子推向稳定位置的向量）。这次比赛官方直接白送了海量这种"标准答案"：2500 万帧的逐原子受力、3200 万个构象的能量。于是预训练任务就是：

> 输入分子结构 → 模型输出"能量"和"每个原子的受力" → 和 DFT 标准答案算 MSE（均方误差）。

类比到 LLM 世界，相当于：不只是让模型猜被遮住的词，而是每个句子都附带一个语言学家标注的"语法正确性得分"和"每个词的句法角色"，你拿几百万条这种标注做监督预训练。这就是为什么它叫**有监督预训练**——监督信号不是来自下游任务标签，而是来自物理定律。模型为了算准能量和力，必须内化"什么样的结构稳定、什么官能团贡献多少能量"，而这些恰好是溶解度、毒性、带隙等下游性质的底层原因。

**4. 描述符蒸馏（= 让模型学会"查表答案"）**
化学家有一些几十年积累的经典公式（比如 logP 油水分配系数、分子量、氢键供体数），给任意分子用 RDKit 软件一毫秒就能算出来。预训练时让模型的一个输出头去回归这 200 个数值。这个 loss 的妙处不在"学会算描述符"（反正 RDKit 会算），而在于**强迫模型把这些性质信息写进中间层表征里**——下游那个只允许 100K 参数的小 MLP 就能很容易地"读"出来。类比：训练 LLM 时额外要求它预测每句话的词数、情感分、主题标签，它的隐层就自然会组织成"这些信息容易被线性读出"的样子。

## 三、所以"继续预训练"的操作流程，其实你都会

整个 pipeline 和你做 LLM continue-pretrain 的工程动作一模一样：

1. **造语料**：把分子的 (原子, 键, 坐标) 序列化成模型输入（相当于 tokenize），能量/力/描述符作为标签字段——就是 JSONL 里每行一个样本、带 labels；
2. **配 loss**：总 loss = 掩码原子 CE + 坐标去噪 MSE + 能量 MSE + 力 MSE + 描述符 MSE，各自带权重——和你调 SFT/预训练混合数据配比是同一件事；
3. **加载开源权重继续训**：从 Uni-Mol2 的 checkpoint 出发，在新语料上接着跑——这就是 continue pretraining 的字面意思，还顺便满足赛规"不能用未经改动的开源 Encoder"；
4. **换域时防遗忘**：混入旧域数据 replay、或冻结主干只训 adapter——和你做 LLM 领域续训时防灾难性遗忘的手段完全同一套。

## 四、回到你的问题：如果一定要直觉化理解，就记住一句话

> **LLM 预训练学的是"词与词怎么共现"，分子预训练学的是"原子在空间里怎么排布、排布决定多少能量"。前者靠猜下一个词，后者靠猜被遮的原子、被加噪的坐标、以及物理定律给出的标准答案。**

## 一、拆开看：扩散模型 = 一个训练目标 + 一个采样过程

**扩散模型是两件套：**

1. **训练目标**：给真实数据 x 加噪声 → 让网络预测噪声（或预测原始 x）→ 算 MSE；
2. **采样过程**：生成时从纯噪声出发，**迭代几十到几百步**，每步走一点点，逐步去噪直到得到新样本。

你"不是扩散模型"的直觉，针对的是第 2 件——我们确实**永远不做迭代采样**，因为我们要的不是"生成新分子"，而是"理解已有分子"。

但第 1 件可以单独拿出来用：**只训、不采样**。这时候它就不叫扩散模型了，它有个更老的名字——**去噪自编码器（denoising autoencoder）**，本质上是一种表示学习的前置任务（pretext task），和 BERT 掩码是同一族。

## 二、那"训了不采"图什么？——预测噪声 ≈ 学习能量面

这里有个漂亮的数学事实，也是为什么这个 loss 在分子领域特别合理：

往坐标 x 上加方差为 σ² 的高斯噪声后，"最优的去噪方向"（即模型应该预测出的东西）在数学上正比于 **∇ log p(x)**——数据分布对数密度在 x 处的**梯度方向**，这叫 score matching（分数匹配）。

翻译成分子的语言：

> **"往哪个方向推原子能让这个结构更像真实分子" = 数据分布的梯度 ≈ 物理上"力"的方向。**

回忆上一轮说的：DFT 标注的"逐原子受力"也是把原子推向能量更低（更稳定）位置的向量。所以：

- **坐标去噪** = 从**数据的分布**里隐式学"力场"（不需要任何标注，构象本身就是监督）；
- **受力回归** = 从**DFT 标注**里显式学"力场"（需要官方白送的辅助标签）。

两者学的是同一个物理对象，只是一个免费无标注、一个有标注更准。这就是为什么我把它们放在同一个"物理锚定"组里——它们是互补的两种来源的同一信号。

## 三、实际跑起来是什么样（破除"肯定很贵"的疑虑）

训练时每一步就是一次普通的前向 + 反向传播：

```
取一个真实构象 x
→ 采样噪声 ε ~ N(0, σ²I)，σ 随机取（0.04~1.0 Å 之间）
→ 把 x+ε 喂给 Encoder（原子类型不遮，只污染坐标）
→ 模型输出每个原子的预测噪声 ε̂
→ loss = MSE(ε̂, ε)，反向传播，完事
```

**推理时：不加噪、不迭代、不多步**——干净分子进，表征出，和用 BERT 提句向量一模一样。所以 B 榜那个 encode.sh 里没有任何扩散采样的开销，推理成本和普通 Encoder 完全相同。

这个做法也不是我发明的：Uni-Mol（我们选的 v0 底座）的论文里，3D 预训练任务就是"坐标去噪 + 掩码原子"，它从头到尾是个表示学习模型，没有任何生成功能。同样地，BERT 训练时用了"猜被遮住的词"，但没人拿 BERT 来填空写文章——**预训练任务只是手段，模型最后的用途由你决定**。

4. **affine 初始化**：把训练集标签的均值/方差折进最后一层（规则允许），让探针从"输出训练集中位数"起步——即保底基线分，再往上优化。

## 一、MoLE 是什么：和普通 MoE 的三个本质区别

普通 MoE（混合专家）你熟悉：一个 router 给每个 token 选 top-K 个"专家子网络"，只有被选中的专家参与计算。MoLE（Mixture of **Linear** Experts）是 UMA 为了科学计算改的变体，三个区别正好都踩在本赛题的需求上：

**1. 专家是"线性层"，混合发生在权重上，而不是激活上。** 普通 MoE 是 y = Σ α_k · Expert_k(x)（先各自算，再加权）；MoLE 是先把专家权重矩阵加权合并成一个矩阵，再做一次线性变换：y = W\*·x，其中 **W\* = Σ α_k · W_k**。

**2. 路由只看"全局信息"，不看单个原子。** 决定 α_k 的输入是整个体系的全局特征（在 UMA 里是：DFT 任务类型、总电荷、总自旋）——对同一个分子/晶体是**恒定**的，所有原子共享同一组 α。

**3. 因为前两点，推理前可以"预合并"。** 既然整条轨迹/同一条记录的 α 不变，就能在推理开始时把 W\* = Σ α_k W_k 算出来缓存住，之后前向跑的是一个**普通稠密模型**——所以 UMA-M 总参数 1.4B，但"激活参数"只有 50M，推理速度和不带专家的模型几乎一样。

把上面三个性质映射到赛题约束，会发现它解的正是你最头疼的两个问题：

| 赛题痛点 | MoLE 如何解决 |
|---|---|
| **"保证扩充 domain 时旧 domain 不掉点"**（你四步思路的第 4 步） | 新 domain = 新增一个"任务条件嵌入"，路由到不同的专家组合。**旧 domain 的路由向量不变 → 它的合并权重 W\* 不变 → 前向计算路径数学上不变**。这把"防遗忘"从经验目标（靠 replay 赌）变成了结构保证 |

## 二、多领域不掉点：LLM 持续预训练的工具箱几乎能整个搬过来

这个问题在 LLM 领域叫 **continual pretraining 的灾难性遗忘（catastrophic forgetting）**，已经有一整套成熟打法。按"推荐优先级"映射到你的四域扩展：

### 1. 数据回放 replay（最便宜，必做）
LLM 领域续训的标准做法就是**新旧语料按比例混**（比如新域 70–85% + 旧域回放 15–30%）。你完全照搬：训晶体能量/力时，混入 GEOM 构象的掩码/去噪任务；训聚合物时混入小分子数据。成本几乎为零，防遗忘效果立竿见影。

### 2. 参数隔离（最强保证，推荐为主力）
LLM 界的对应物是 **LoRA/Adapter 持续学习**：冻结主干，每个新域只训自己的 adapter，旧域的计算路径**数学上不变**——这不是"尽量不掉点"，是"结构上不可能掉点"。在你的场景里这个角色就是 **MoLE/adapter**：新域加新专家或新 adapter，主干冻结。这也顺便契合赛题"按领域路由"的合规空间。

### 3. 知识蒸馏 KD（防表征漂移）
LLM 持续学习里的常用招：新模型在旧域数据上，除了正常 loss，再加一项"**输出向旧模型的输出靠拢**"的蒸馏 loss。映射过来：续训时让新 Encoder 在小分子验证切片上的表征，和续训前 checkpoint 的表征保持接近（MSE 或对比蒸馏）。相当于给表征空间加了一个"锚"，防止训新域时整个空间被拧歪——这比只保任务分数更深一层，因为**你的交付物本质是表征本身，表征漂移 = 已训好的全部 MLP 作废**。

### 4. 学习率纪律（细节但常翻车）
LLM 经验：续训用**比从零预训练低一个量级的学习率 + 短 warmup**，遗忘程度和学习率高度正相关。你的场景同理：Uni-Mol2 续训别开大步长，尤其 W4 封板前的最后微调。

### 5. 权重合并 model soup（进阶选项）
LLM 界近两年的玩法（model soups / WiSE-FT）：新域单独训一份权重，然后和旧权重做**插值平均**（α·新 + (1−α)·旧），用看板挑 α。成本低到只要一次前向验证，适合作为"训练后发现轻微掉点"的补救手段，不用重训。

## 一、Uni-Mol 为什么能做肽：因为肽本来就是分子

肽不是什么特殊存在——它就是氨基酸通过肽键连起来的**一个普通有机分子**，只是个头大（一条 30 残基的肽约 400–600 个重原子）。所以"PepLand 论文里 Uni-Mol 做肽任务"的做法朴素得惊人：

1. **3D 构象是假象**。Uni-Mol2 要吃 3D 坐标，肽的输入只有序列，你得用 RDKit ETKDG 现生成分子构象——但对几百个原子的高柔性肽链，ETKDG 生成的构象**物理意义很弱且非常慢**（比小分子慢一两个数量级）。48K 条 DBAASP 的构象生成要按小时计，而且 B 榜时限内 encode.sh 里现生成可能来不及——构象要预生成缓存，或干脆肽线走 2D 图模式。这正是 PepHarmony 那篇"训练用结构、推理只用序列"设计的动机。
2. **逐残基任务 Uni-Mol2 给不了**。BIO-A-2（PEER）里的逐残基分类要求输出 tokens.npy（每个残基一行表征）。Uni-Mol2 的 token 是**原子**不是残基，把原子表征聚合成残基表征需要额外的映射层——可以做（PepLand 的 fragment view 本质就是干这个），但这是改造工作，不是开箱即用。
3. **PepLand 仓库本身的两个使用提示**：它提供现成的 `PepLandFeatureExtractor`（肽 SMILES → 300 维嵌入，pip 级易用），但它也是开源模型，最终提交同样需要改造声明；而且仓库注明**两步预训练的完整数据未随代码发布**（"see the maintainer's public data announcement"），想复现它的预训练要先确认数据可得性。另外它的 fragment vocabulary 和 checkpoint 是绑定的，换词表就要重建预测头——自己改的时候别踩这个。

## 一、先纠正对"统一 Encoder"的理解

赛题原文对 Encoder 的要求只有三条：

> 1. "参赛者提交一个统一的Encoder，**架构和输入模态不限**"
> 2. "Encoder在所有下游任务的评测中必须**冻结共享**"
> 3. "**同一领域**的所有子集使用同一套处理，不得按**数据集名、子集名或记录id**分支"

注意第三条禁止的分支粒度是"数据集/子集/记录"，而 submission.json 里表征维度 D 本来就是**按领域声明**的。所以"统一"的真实含义是：**一个权重文件、一个加载入口（encode.sh）、一个冻结的交付物**——而不是"所有记录必须流过同一组权重"。

一个贴切的类比：**多模态 LLM 也是"一个模型"，但图片走 vision tower、文字走 text tokenizer，没人说 CLIP 是"两个模型"**。你的 Encoder 也是同理：一个包裹里装着四条塔，按记录自带的 sample_type 路由。

## 二、用 CATH 的一条记录走完整个推理

假设 B 榜评测时，主办方运行 `bash encode.sh <INPUT_DIR> <OUTPUT_DIR>`，INPUT_DIR 里有一条蛋白记录（标签已删除）：

```json
{
  "id": "cath_000123",
  "sample_type": "protein",
  "inputs": {"sequence": "MKTAYIAKQRQISFVKSHFSRQ..."}
}
```

encode.sh 内部的完整流程：

```
第1步：读 JSONL，逐条取出记录
        ↓
第2步：加载唯一 checkpoint（一个 safetensors 文件，
       里面装着全部四条领域前端 + 共享部分 + 路由表）
        ↓
第3步：路由器读 sample_type="protein"
       → 分发给 BIO 前端（即改造续训过的 ESMC-600M）
       【这一步就是"领域前端"的全部含义：一个 if 分支，
         分支依据是记录自身的合法字段，不是数据集名或 id】
        ↓
第4步：序列 "MKTAYIAK..." 切成残基 token [M, K, T, A, ...]
       → 过 ESMC 权重 → 得到逐残基隐状态 [L=247, 1152]
        ↓
第5步：读出层（属于 Encoder 本体，已冻结）：
       - 多层加权求和 → 投影 → 序列向量 [1024]
       - 逐残基投影 → [247, 1024]（给逐残基任务备用）
        ↓
第6步：写文件（赛题规定的表征契约）：
       embeddings.npy 第 i 行 = 这条记录的 [1024] 向量
       ids.txt 第 i 行 = "cath_000123"
       （PEER 的逐残基子集额外写 tokens.npy = [ΣL, 1024]）
        ↓
第7步：主办方的 mlp_infer.py 读取表征 + 你提交的
       MLP 描述文件和权重（≤2层、≤100K参数）
       → 输出预测 → score.py 计分
```

同一批输入里如果下一条记录是 `sample_type="molecule"`，第 3 步就把它路由给 Uni-Mol2 前端；`sample_type="crystal"` 就路由给 PBC 晶体前端。**对主办方来说，它只看到：一个 encode.sh、一个 checkpoint、一堆 embeddings.npy**——这就是"统一 Encoder"的全部外在表现。

## 三、ESMC 在这里到底是什么角色

ESMC 是 **BIO 前端的初始化权重**，不是最终交付物本身。它和你方案的关系分三层：

1. **结构上**：它是"统一 Encoder 这个包裹"里的一个组成部件——蛋白塔的骨架；
2. **权重上**：最终提交的 checkpoint 里，蛋白塔这部分**必须是你续训/改造过的 ESMC**（比如在 MegaScale 261 万序列 + DBAASP/PEER/CATH 的无标签序列上做了领域 MLM 续训，可能还加了投影层），而不能是官方原版权重；
3. **合规上**：它对应两条规则的交叉点——"架构不限"（允许你用它）×"禁止未经改变的开源 Encoder"（要求你改它并有训练记录）。

## 五、那"统一主干"又是什么？——它是加分项，不是必需品

之前架构图里的"共享主干"（MoLE 那套）是一个**可选的升级**，目的是让四个领域之间有信息交换（比如晶体的能量知识可能帮小分子），并且答辩时"我们真正统一了表征空间"的叙事更漂亮。**最小可行版本完全可以没有它**：四条前端各自产出本领域的表征，各自声明维度 D，直接拼进一个 checkpoint 交付——这在规则上同样成立。

所以整个概念的层次是：

```
统一 Encoder（交付物视角）
= 一个 encode.sh 入口
+ 一个 checkpoint 文件，内含：
    ├── 路由器（按 sample_type 分支）
    ├── 小分子前端（续训改造版 Uni-Mol2）
    ├── 聚合物前端（PSMILES 序列塔）
    ├── 晶体前端（PBC 等变图网络）
    ├── 蛋白/肽前端（续训改造版 ESMC-600M）  ← ESMC 在这
    └── [可选] 共享主干 + MoLE（跨域对齐用）
+ 各领域的读出层（产出声明维度 D 的表征）
```

一句话收束：**"分领域前端"不是架构创新，而是对规则空间的合法利用——赛题按领域声明维度、禁止的是数据集级分支，那么"一个包裹、四条塔"就是最自然的形态；ESMC 是蛋白塔的起点权重，续训改造后进包裹，推理时被路由器选中、产出表征、落盘，MLP 在表征之上跑——全链条每一步都对应着赛规的一条具体条款。**

## 一、unimol_tools 路径：从 SMILES 到模型输入的完整流水线

你跑 `UniMolRepr(data_type='molecule').get_repr(smiles_list)` 时，内部发生的事：

**第 1 步：DataReader 读入**
把 SMILES 列表/CSV/SDF 统一解析成字典格式 `{'atoms': [['C','C','O',...]], 'coordinates': [np.array(N,3)]}`。如果你直接给 dict（原子列表 + 坐标数组），就跳过构象生成——**这对竞赛很关键，下面细说**。

**第 2 步：ConformerGen 生成 3D 构象**（只给了 SMILES 时）
核心调用链是 RDKit 经典四连：

```python
mol = Chem.MolFromSmiles(smi)          # ① SMILES → 分子图（含键级、芳香性）
mol = Chem.AddHs(mol)                  # ② 补氢（构象生成需要）
AllChem.EmbedMolecule(mol, AllChem.ETKDGv3())   # ③ ETKDG 构象嵌入
AllChem.MMFFOptimizeMolecule(mol)      # ④ MMFF 力场优化
coords = mol.GetConformer().GetPositions()      # ⑤ 取坐标
```

然后根据 `remove_hs` 参数决定去不去氢（Uni-Mol 默认去氢，用重原子图）。**你的 319 条失败，绝大多数会死在这一步**：①的 sanitize 失败（kekulization、价态异常）或③的 EmbedMolecule 不收敛（默认失败返回 -1，需要 `useRandomCoords=True` 兜底）。

**第 3 步：DataScaler 标签标准化**
回归标签用训练集均值/方差做 z-score，预测时反变换——这与比赛 MLP 规范里"回归 affine 可折进最后一层"是同一个东西。

**第 4 步：模型侧特征化（真正喂给 Transformer 的张量）**
每条分子最终变成四个张量：

```python
input_ids   : [N]      # 原子 token id，查 dict.txt 词典（元素符号 → 整数）
coords      : [N, 3]   # 原子坐标，先做居中归一化（减去质心）
dist_mat    : [N, N]   # 成对欧氏距离 → 高斯核展开（见下）
edge_ids    : [N, N]   # 成对"边类型 id" = 键类型 + 最短路径 SPD 的联合编码
```

## 二、特征的具体定义（论文公式 2–3 + 附录 A.2）

这是 Uni-Mol2 区别于普通图网络的核心——**原子、键、拓扑、几何四个层面的特征同时进模型**：

**原子表示初始化**（论文公式 2）：
$$x_{atom}^i = \text{Embedding}(x_{token}^i) + \text{Embedding}(x_{degree}^i) + \text{Embedding}(x_{atomic}^i)$$

三个成分分别来自：
- `x_token`：元素符号查词典的离散 id；
- `x_degree`：原子的连接度（几个邻居）；
- `x_atomic`：RDKit 算的原子特征向量（附录 Table 7：形式电荷、自由基电子数、杂化方式 sp/sp²/sp³、是否芳香、是否在环上等，都是 one-hot 拼接）。

**原子对表示初始化**（论文公式 3）：
$$x_{pair}^{i,j} = \text{Embedding}(x_{bond}^{i,j}) + \text{Embedding}(x_{SPD}^{i,j}) + \psi^{i,j}$$

- `x_bond`：键特征（附录 Table 8：单/双/三/芳香键、是否共轭等），非键连原子对为"无键"类；
- `x_SPD`：**分子图上两原子的最短路径跳数**，用 Floyd-Warshall 算法算（注意：这是纯拓扑量，只依赖键，不依赖 3D 坐标）；
- `ψ^{i,j}`：**欧氏距离的高斯核展开**——对每对原子的 3D 距离 d，用一组预设均值/方差的高斯基函数展开成向量（`exp(-(d-μ_k)²/2σ_k²)`，k 个核），这是把连续距离"token 化"的标准做法。

所以一个分子的输入形状大约是：`atom [N, d_a]` + `pair [N, N, d_e]`，其中 N 是重原子数（QM9 最多 9 个重原子，很小），pair 矩阵存储开销可以忽略。**这也是为什么 QM9 是 Uni-Mol2 最舒服的任务**——分子小、元素只有 CHONF 五种、全在预训练分布内。

## 三、预训练路径的装饰链（官方 unicore 代码，真实函数名）

从仓库 issue 里拿到的 `unimol2.py` 的 `load_dataset`，数据流是一串 dataset 包装器：

```python
LMDBDataset(data, split, epoch)                    # 从 LMDB 读 {smi, atoms, coordinates}
→ Add2DConformerDataset(...)                       # 补一个 2D 投影坐标（drop 3D 时用）
→ ConformerSampleDataset(..., conf_size=11)        # 每个分子采样构象（10个3D + 1个2D）
→ RemoveHydrogenDataset(atoms, coordinates, True)  # 去氢，只留重原子
→ CroppingDataset(..., max_atoms)                  # 超 max_atoms 的分子裁剪/丢弃
→ NormalizeDataset("coordinates", normalize_coord=True)  # 坐标居中归一化
→ IndexAtomDataset(smi, atoms)                     # 原子符号 → 词典 id
→ Unimol2FeatureDataset(                           # 训练时的在线扰动：
      mask_token_prob=0.15,      # 15% 原子 token 打 [MASK]
      noise=0.2, noise_type=..., # 坐标加 σ=0.2 高斯噪声
      drop_feat_prob=1.0,        # 微调时 100% 丢原子/键/SPD 特征 → 纯 3D 模式
      ...)
```

注意最后一个参数 `drop_feat_prob`：官方 QM9 微调脚本里设的是 **1.0**——即微调时**完全丢弃**原子特征、键特征、SPD 特征，只留 atom token + degree + 3D 坐标。原因正是论文里那句你要记住的话：

> "由于 QM9 数据集只提供构象，部分分子无法正确生成原子与键特征"

## 四、映射到竞赛 QM9：你和论文处境的关键差异

论文的 QM9 是"只有构象没有 SMILES"的版本，键特征要从 xyz 反推化学键（xyz2mol 类），天然会挂一批分子。**而竞赛的 QM9 输入是 SMILES + 3D 构象双输入**，这意味着你的最优做法是：

1. **键/拓扑特征从 SMILES 生成**（RDKit 图，100% 可靠，不走 xyz2mol）；
2. **坐标直接用官方给的 3D 构象**——QM9 的 alpha/r2/zpve/cv 都是在 **DFT 优化几何**上算的性质，官方构象就是 DFT 几何，比 ETKDG+MMFF 现生的构象物理意义强得多。这正好绕开构象生成步骤，也绕开你那 319 条失败的一大来源；
3. **必须做原子顺序对齐**：SMILES 解析出的原子顺序和 SDF/构象文件里的原子顺序**不一定一致**，特征构建前要用 RDKit 的子结构匹配或映射把两者对齐——这是这条路线上最容易静默出错的地方（错位不会报错，只会悄悄喂错坐标）。

## 五、回到你的 681/319

结合上面，失败原因按可能性排序：① SMILES sanitize/kekulization 失败（打印 `MolFromSmiles` 返回 None 的数量即可确认）；② ETKDG 嵌入失败且没加随机坐标兜底；③ 如果你试图从构象反推键，撞上论文承认的那个坑。修法：按第四节改成"SMILES 给图 + 官方构象给坐标"的双源构建，并把每条失败样本的具体异常分类统计——这一步修完通过率应到 99% 以上。

另外一个顺手能拿到的收益：改成用官方构象后，你的表征是"DFT 几何条件下的表征"，这对 alpha、zpve 这类强几何依赖的性质是实打实的分数提升，而不只是修复失败率。
