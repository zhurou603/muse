# S5 四天执行手册

## 0. 执行原则

这四天不再扩展模型、替换 tokenizer、引入新架构或开启新 pilot。唯一训练主线是固定 S5 课程；唯一高频选模口径是固定 robust validation；唯一可自动更新的候选指针是 best_fixed。latest/final 只用于恢复，best_fixed 只表示固定头协议最佳，二者都不是正式 A/B 榜成绩。

“每天四领域都涨分”不是可保证的控制目标。实际执行采用：官方加权 `J_encoder_fixed` 最小增量＋四领域遗忘门＋shadow-B 遗忘门。晶体接近满分时允许小幅波动，不允许为了其他领域收益而明显退化。

## 1. 第 0 阶段：启动前，先验收再占用 7×24 小时连续算力

### 1.1 冻结现状

- 备份 S1–S4 配置、训练日志、父 checkpoint、原评估结果和正式提交文件。
- 记录父 checkpoint 的绝对路径、字节数和 SHA256。
- 如果 S4 replay-only control 尚未完成完整 90 项、8/8 shadow-B 和领域非退化验收，就先使用 DBAASP step 300；不要把“control 理论更合理”当成已验收。
- 确认新 `RUN_DIR` 不存在或为空，正式旧 run 不被覆盖。

### 1.2 安装与测试

按 README 完成安装、compileall、单元测试、shell 语法检查和长序列集成测试。原机还要做：

- 生产 `load_tokenizers()` 长序列测试；
- RDKit 可用性与 PI1M 10,000 条均匀 row/view 审计；
- 官方 scorer 与真实 manifest 加载；
- 所有训练输入、目标统计、索引、排除 hits 和 OMC25 资产的数据清单；
- 外部血缘审计。当前“待核验”模板预期失败，不得删除检查来伪造通过。

### 1.3 1-step 与 50-step 小验收

先不要用自动重启脚本。使用单独 smoke run，确认非正式目录：

```bash
export S5_PACKAGE=/path/to/S5完整连续训练交付
export REPO_ROOT=/path/to/项目根目录
export PYTHONPATH="$REPO_ROOT/code/model_design:$S5_PACKAGE:${PYTHONPATH:-}"
export CONFIG="$REPO_ROOT/code/model_design/configs/s5_continuous.yaml"
export SMOKE_RUN=/data/runs/S5_smoke_$(date +%Y%m%d_%H%M%S)
export PARENT=/path/to/自己的父checkpoint.pt
export CUDA_VISIBLE_DEVICES=0,1,2,3,4,5,6

# 第一段只到绝对 step 1。
torchrun --standalone --nproc_per_node=7 -m muse_encoder.s5.train \
  --config "$CONFIG" --run-dir "$SMOKE_RUN" \
  --init-weights "$PARENT" --stop-after 1

# 第二段从 step 1 恢复到绝对 step 51，验证 warmup、周期课程和恢复。
torchrun --standalone --nproc_per_node=7 -m muse_encoder.s5.train \
  --config "$CONFIG" --run-dir "$SMOKE_RUN" \
  --resume "$SMOKE_RUN/latest.json" --stop-after 51
```

验收点：

- `step_00000000.pt` 在首步前已经存在；
- `latest.json` 的 step、path 和 SHA256 一致；
- 每个 rank 都有对应 RNG sidecar；
- resume 后从旧 micro_step 继续，没有重放已经完成的 optimizer step；
- `course_rank*.jsonl` 的 source 在 rank 间一致，row/view 可以不同；
- 20-step 领域槽位和 DBAASP 微课程比例符合单测；
- OMC25 的 force=30 只出现在晶体槽位，分子批次 force 权重为 0；
- loss、梯度、学习率均有限，warmup 后 LR 恒定；
- 在 step 50 附近人为停止一次，再从 latest 恢复到 51，确认故障恢复不是只在正常退出时可用。

smoke run 不能更新 best_fixed，不能覆盖正式 RUN_DIR，也不能被写成“全量训练通过”。

### 1.4 建立父模型 baseline

用父模型显式运行一次 `evaluate_candidate --mode full --bootstrap`。只有完整 90/90、非 smoke、固定协议标记、shadow-B 8/8 和 Encoder coverage 都合格，才建立 best_fixed。baseline 与候选必须使用同一 validation、同一 MLP 搜索空间、同一组种子和同一数据版本。

## 2. 第 1 天：启动主线，先证明流程连续

1. 用正式空 `RUN_DIR` 启动训练脚本和独立 watcher。
2. 观察首批 step 0、100 的模型、优化器、scheduler、TrainState、RNG 和 course 日志是否齐全。
3. 首个 sentinel 只检查能否完成编码、MLP 和结果落盘；不把 smoke 分数当成完整 90 项。
4. 首个 full 按固定协议比较父模型。若拒绝，读取 `decision.json` 的具体原因，不修改 best，不立即换课程。
5. 仅在 best_fixed 接受新候选后，才考虑当天一次正式 A-test；否则保留旧正式交付，不为“每天必须提交”而提交 latest。

当天需要回答的问题不是“Loss 是否每个都下降”，而是：

- 数据读取是否持续，是否存在单来源卡死或异常回退；
- checkpoint/resume 是否能经受真实中断；
- 异步评估是否只读训练目录；
- full 候选是否因完整性、coverage、总分增量或遗忘门被拒绝；
- 磁盘增长和实际步速是否支持后续三天。

## 3. 第 2 天：只看同口径趋势，不换训练目标

- 保持课程、模型、tokenizer、优化器参数和 fixed probe 不变。
- 比较第 1 天与第 2 天 full 的领域分、90 项缺失、shadow-B 和 `J_encoder_fixed`。
- 查看 `course_rank*.jsonl`，确认四个领域及关键数据集确实被采样，而不是配置写了但运行没有走到。
- 聚合新出现的失败/回退记录。预测完整率与 Encoder coverage 分开报告。
- 如果总分上涨但某领域超门限遗忘，候选仍拒绝；如果总分没有超过最小增量，也保留旧 best。
- 连续多个候选被拒绝时先检查数据、头、评估口径和遗忘原因，不要临时恢复已失败的 S4 treatment。

当天最多一次正式 A-test，只使用当前已接受 best_fixed。不要用 A-test 反复挑选随机种子或调整 MLP。

## 4. 第 3 天：保留交付裕量，准备锁定候选

- 继续同一训练，不因短期平台波动重启新课程。
- 对当前 best_fixed 再检查完整结果文件、冻结 checkpoint SHA256、数据清单和推理包版本。
- 将父模型、历史 best、当前 best 和正式 A-test 输入分别保存，路径不得互相覆盖。
- 对正式交付候选运行既有完整 A-test/提交流程；仍遵守每天最多一次。
- 汇总 23479 条历史失败/回退和 S5 新增记录，按 source/reason 分类，不能用 90/90 status=ok 掩盖记录级问题。
- 提前确认 B 榜锁定流程：同一 Encoder、同一特征器、同一推理包生成 B train/validation/test 表征，B 阶段不再更新 Encoder。

## 5. 第 4 天：停止追新，完成可复现交付

1. 预留足够时间做最后一次 full 和正式流程，不在截止前几分钟更换 checkpoint。
2. 最终选择已验收 best_fixed，不自动选择 step 最大或 loss 最低的 latest。
3. 固化模型、配置 resolved YAML、父模型血缘、数据 manifest、课程日志、评估 decision 和提交文件 hash。
4. 运行推理 smoke，核对 D=1024、90 项输出、无缺失、无非法预测和 MLP 参数预算。
5. 如果最后候选被拒绝，直接回滚到上一个 best_fixed；如果新 best 的正式流程异常，回滚到已确认可用的历史交付。
6. B 榜开始前锁定推理包，之后不更新 Encoder，不混用不同 checkpoint 的表征。

## 6. 停止、重启与回滚条件

### 必须停止自动重启并检查

- 数据文件缺失、大小或 SHA256 不匹配；
- 出现非 train 标签、未知 source、非法外部标签或第三方预训练权重；
- loss/grad 非有限，或连续重启不能消除同一数据错误；
- 生产 RDKit/特征化错误超过既定门槛；
- 磁盘不足，无法原子保存模型和 RNG；
- DDP rank 的 course source 不一致或 RNG sidecar 缺失。

### 不需要停止训练，但候选必须拒绝

- full 不是 90/90 或 shadow-B 不完整；
- `J_encoder_fixed` 增量不足 0.02；
- 任一领域或 shadow-B 遗忘超过阈值；
- Encoder 缺失/回退比例超过 0.001。

### 回滚方式

训练和评估本来就使用不同目录。拒绝候选不会修改 best_fixed，因此回滚是选择既有冻结 checkpoint，而不是把旧权重覆盖回正在训练的 latest。只有明确决定放弃整段 S5 时，才停止训练并重新从父模型开启一个新 run；不得删除失败现场和审计记录。
